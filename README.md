# نظام بوستات زيادة

وحدة محتوى واحدة في ملف YAML، تتحول إلى شرائح مصممة بهوية زيادة، تُرفع على
GitHub، وتُنشأ كمسودات في بفر للمراجعة قبل النشر.

---

## التهيئة، مرة واحدة فقط

### 1. فك الأرشيف وادخل المجلد

```bash
tar xzf ziadah-social.tar.gz
cd ziadah-social
```

### 2. ثبّت المتطلبات

```bash
pip install -r requirements.txt
python3 -m playwright install chromium
```

`playwright install chromium` ينزّل متصفحاً كاملاً، حوالي 150 ميجابايت،
ويستغرق دقيقة أو دقيقتين. هذا هو محرك الرندر: نفس محرك كروم، فالذي تراه
في المتصفح هو بالضبط ما يخرج في الصورة.

### 3. أنشئ ريبو **public** على GitHub واربطه

```bash
git init
git add .
git commit -m "init: نظام بوستات زيادة"
git branch -M main
git remote add origin https://github.com/<اسمك>/ziadah-social.git
git push -u origin main
```

**الريبو لازم يكون public.** `raw.githubusercontent.com` لا يخدم الريبو
الخاص بلا توكن، وبفر لن يستطيع جلب الصورة. لا تضع في هذا الريبو أي شيء
غير مخصص للنشر العلني.

الشرح الكامل لطبقة GitHub، من المصادقة إلى جدول الأعطال، في
[`docs/github.md`](docs/github.md).

السكربت يقرأ المالك والريبو والفرع من `git remote` مباشرة، فلا يوجد ملف
إعداد تكتبه يدوياً ولا يوجد شيء يتعفّن.

### 4. تأكد أن موصّل Buffer مربوط في كلود كود

من داخل كلود كود اسأل:

> اعرض لي قنوات بفر المتاحة

المفروض يرجّع ثلاث قنوات: `ZiadahApp` على X، و`ziadahapp` على انستقرام،
و`Ziadah | زيادة` على لنكدن. إذا ما رجّعها، اربط موصّل Buffer أولاً.

## الدورة الأسبوعية

### الخطوة 1: جهّز الوحدة

من داخل كلود كود:

> جهّز وحدة الأسبوع القادم عن [الموضوع]. انسخ
> `content/posts/2026-08-02.yml` باسم تاريخ الأحد القادم، واكتب النصوص
> الثلاثة، وعدّل العنوان في القالب.

كلود كود يقرأ السكِل في `.claude/skills/ziadah-social/` فيعرف الأرقام
المعتمدة والقواعد والمواعيد بلا ما تعيد شرحها.

راجع الملف الناتج بنفسك قبل الخطوة التالية.

### الخطوة 2: ارندر وارفع

```bash
python3 scripts/publish.py content/posts/<التاريخ>.yml
```

المخرج المتوقع:

```
1) الرندر والفحص
فحص التخطيط: سليم
2) التصدير JPEG
   unit-b-moments-01.jpg  144 KB
   unit-b-moments-02.jpg  182 KB
3) الدفع إلى GitHub
   <اسمك>/ziadah-social @ main
   مدفوع
4) التحقق أن الروابط تخدم صوراً
   unit-b-moments-01.jpg  image/jpeg  144 KB
   unit-b-moments-02.jpg  image/jpeg  182 KB
5) المانيفست
   out/<التاريخ>/manifest.json
```

**إذا توقف عند الخطوة 1** فالفاحص وجد مشكلة: سقوط الخط، أو تراكب كتلتين،
أو نص يعبر خط اللحام فينقسم، أو تجاوز الهامش الآمن. الرسالة تقول أي عنصر
وأين بالضبط. أصلح القالب وأعد التشغيل. لا تعطّل الفاحص.

**إذا توقف عند الخطوة 4** فالرابط لا يرجّع صورة. غالباً الريبو خاص، أو
الدفع راح على فرع غير الذي تعمل عليه.

### الخطوة 3: راجع الشرائح بعينك

```bash
open out/<التاريخ>/canvas_full.png
```

`canvas_full.png` يعرض الشريحتين متجاورتين فتتأكد أن الاتصال بينهما
سليم. هذه الصورة مرجع داخلي ولا تُنشر.

### الخطوة 4: أنشئ المسودات

من داخل كلود كود:

> اقرأ `out/<التاريخ>/manifest.json` وأنشئ المسودات في بفر

كلود كود ينشئ منشوراً لكل عنصر بحالة `saveToDraft`، ثم يتحقق بـ
`list_posts` أن العدد صحيح ويخبرك كم مسودة أُنشئت وعلى أي قنوات.

**لا شيء ينشر تلقائياً.** كلها مسودات.

### الخطوة 5: اعتمد من بفر

افتح بفر، راجع كل مسودة، عدّل ما تحتاج، وحوّلها إلى مجدولة. هذه هي
النقطة الوحيدة التي يخرج فيها شيء إلى الجمهور، وهي بيدك.

## المواعيد

الجدول مبني على أن أسبوع العمل السعودي أحد إلى خميس، وأن قرارات العمل
تُقرأ صباحاً على لنكدن بينما التفاعل الشخصي يجي ليلاً على X وانستقرام.

| اليوم | القناة | الوقت |
|---|---|---|
| الأحد | LinkedIn | 10:00 ص |
| الأحد | Instagram | 9:00 م |
| الأحد | X | 9:30 م |
| الثلاثاء | LinkedIn | 10:00 ص |
| الثلاثاء | X | 9:30 م |
| الخميس | Instagram | 8:30 م |
| الخميس | X | 9:30 م |

سبعة منشورات من أصل عشرة تسمح بها الخطة المجانية. الثلاثة الباقية
احتياطي للترند والمناسبات، لأن الترند لا ينتظر الجدول.

## قواعد المحتوى

هذه مكتوبة أيضاً في السكِل فيلتزم بها كلود كود تلقائياً:

- الأرقام المعتمدة فقط: `20M+` مبيعات إضافية، `40M+` ظهور، `200K+` منتج
  إضافي، `1,500+` متجر. **بلا ذكر اسم أي متجر.**
- لا سعر باقة في أي منشور. الأسعار تتغير ولم تُعتمد للنشر.
- لحظات التشغيل الموثقة ثمان. لا تكتب "أكثر من 10" لأنها غير موثقة.
- معرّفات القنوات من `content/channels.yml` فقط، لا تُخمَّن.

## أوامر أخرى

**تجربة الرندر بلا رفع:**
```bash
python3 scripts/render_slides.py templates/carousel_connected.html out/test
```

**إعادة توليد الشعار من ملف جديد:**
```bash
python3 scripts/trace_logo.py /مسار/الشعار.avif
```
يفصل الشكل عن خلفيته ويحوّله SVG. اضبط `THRESHOLD` إن كان الشعار الجديد
بتباين مختلف.

**إعادة بناء ملف الخط:**
```bash
npm pack @ibm/plex-sans-arabic && tar xzf ibm-plex-sans-arabic-*.tgz
python3 scripts/build_font_css.py
```

## وكيل كلود كود

`.claude/agents/social-media-plan.md` يعرّف وكيل **خطة السوشال ميديا**.
هو للعمل عند الطلب، والكرون للتشغيل الأسبوعي بلا تدخل. الاثنان يقرآن
نفس `content/quarter.yml`، فلا يتعارضان.

استدعِه بأي من هذي، أو دع كلود يستدعيه تلقائياً من الوصف:

```
جهّز وحدة الأسبوع القادم عن الكوبون بعد الشراء
غيّر عنوان شريحة 2026-09-06
أضف بوست ليوم التأسيس
خطة السوشال ميديا: وين وصلنا؟
ابنِ لي الربع القادم
```

**اسم الملف والحقل `name` لاتيني وليس عربياً** عن قصد: الحقل يُستخدم
كمعرّف في الاستدعاء وفي مسار الملف، والعربية فيه غير مضمونة. الاسم
العربي "خطة السوشال ميديا" مكتوب في `description` فيستدعيه كلود عند
ذكره.

النطاق مشروعي: الوكيل يعمل داخل هذا المجلد فقط. لتفعيله في كل مشاريعك
انسخ الملف إلى `~/.claude/agents/`.

## معلق

- **قفل الشعار الكامل.** الرمز متجهي مطابق للأصل، لكن كلمة "زيادة"
  مصفوفة بخط IBM Plex ولم تُتتبّع من ملف رسمي. إن وصل القفل الرسمي
  استبدله في `templates/`.
- **الإيميل.** مؤجل. Brevo فيه مرسل واحد على gmail، وهذا يفشل توافق
  DMARC ويرمي الرسائل في السبام. يحتاج تفعيل نطاق `ziadah.app` داخل
  Brevo أولاً، وتنظيف قائمة التجار من التكرارات والإيميلات الداخلية.
- **سكربت الترندات.** لم يُبنَ بعد. المصادر المجانية المخططة: Google
  News RSS بالعربية، وGoogle Trends بنطاق `geo=SA`، ومدونتا زد وسلة.
- **بقية القوالب.** نمط الإحصائيات، نمط الخاصية الجديدة، ونمط المناسبات
  السنوية. كلها ترث نفس التوكنز ونفس سكربت القص.
